# Actual FastIO reader regressions

`Run-Reader.ps1 -Arch x64 -Layout standard` compiles and executes the entire shipping `fastio_packet_filter.h` class. Run x86/x64 with `standard`/`jumbo`; `tests/run_all.cmd` covers all four. No driver is opened. API, adapter/event glue, guarded test allocations, reader atomic scheduling, and reader copy interception are substituted explicitly; the class, allocations requested by `init_filter`, wire types, drain helper, and routing worker are real.

The 235 baseline-compatible worker assertions cover all four sections, actual packet storage and both pointer allocations, exact payloads and ordered identities in each output direction, mixed pass/revert, zero/invalid/regressing counts, stop cleanup, and event behavior without a queue fallback. A deterministic writer prechecks the reader flag, then reserves/copies/completes packet 3 immediately before reset. This complete race is distinct from the pending-writer test, whose old failed completion correctly requeues. Multiple-tail synthetic schedules exercise robustness; they do not promise delivery against malicious shared-memory corruption.

Another 35 assertions call the actual private helper with less remaining capacity than a physical section: initially insufficient, exact fit, and a completed late writer that grows the count past remaining capacity after failed reset CAS. They check refusal before any excess-tail copy, no published count, preserved unconsumed header, released claim, and unchanged destination beyond capacity. Private copied staging remains unpublished when validation fails.

The maintained runner captures source/fixture hashes before and after compilation/execution, owns a hidden process, drains both output pipes, enforces a 30-second runtime bound, checks a numeric exit, and rejects missing/duplicate/nonterminal/inconsistent footers or incomplete assertion counts. Exit 0 is GREEN, 1 is a completed failing test, 2 is setup/invalid evidence. Unsafe baseline copies are intercepted before memory access, and pathological polling aborts after 128 atomic calls. These aborts are failed assertions, not successful production rejection.

`Run-Ablation.ps1 -Arch x64 -Layout standard` verifies two separate exact failure contracts. The frozen pre-fix Git blobs at `0b0f21fddd0032b0b236b01d35ea4145bec4d0e7` run the worker-only 235 assertions (43 failures standard, 27 jumbo), including completed-loss versus pending-requeue trace checks. A one-expression counterfactual disables only the current helper's remaining-capacity refusal and must produce exactly six direct-helper failures out of 270 assertions; physical bounds, cursor, CAS and claim cleanup remain intact. Build errors, crashes, unrelated failures and incomplete runs cannot pass either ablation. `tests/run_all.cmd ablation` includes both contracts for all four layouts alongside the existing historical OID ablation.

All three buffers use four times min(physical slots, 65535). Standard x64/x86 capacities are 8032/8076; jumbo capacities are 1384/1388. The original jumbo allocation was large enough, so its logical-bound assertion is a configuration contract, not a jumbo-overflow finding. x86 executes the actual x86 layout with stubbed FastIO registration; it is not evidence that FastIO registration is supported through WOW64. ARM64/kernel/NIC behavior is outside these offline tests.
