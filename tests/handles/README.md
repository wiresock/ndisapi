# SDK handle and static table regressions

Run from the SDK root with tests\run_all.cmd, or run Run-Handles.ps1 -Arch x64 and -Arch x86 directly. The latter must execute on 64-bit Windows to cover genuine WOW64. VCVARSALL can select a toolchain; otherwise build_handles.cmd uses vswhere.

The fixture extends the independently reviewed Task12a oracle with stale table-map refresh and deterministic snapshot controls. The retained console word 'baseline' identifies that original oracle, not the source being tested. The runner compiles the real SDK translation unit with Win32 I/O and allocation seams. Constructor detection, wire types, mappings, table conversions and public calls remain real. Its x86 executable genuinely takes the WOW64 branch and obtains handles from full 64-bit enumerated identities.

Coverage includes valid and invalid mappings at every forward caller, stable surviving identities after enumeration reorder/removal, the final map slot, unrestricted generic OIDs, immutable SET/ADD/INSERT inputs, terminal-lived private I/O storage, independent immediate/terminal bytes, transactional GET/GET_RESET outputs, count and byte bounds, all returned handle translations, and arithmetic around the exported int byte boundary. A table of 16,385 rules proves that the SDK does not impose the driver's configurable policy cap.

The allocator seam applies only to the SDK translation unit. Large malformed capacities use guard pages; /EHa allows the baseline's faults to become failed assertions and unwind locks. Caught faults are failures, never successful cases. The runner records the source hash before compilation and after execution, preserves the actual child exit, and requires a complete final checks/RESULT footer consistent with that exit. Timeout, crash, source drift and missing/contradictory footers are invalid evidence (runner exit 2), separate from a complete passing or failing test result. The shim does not constitute kernel, NDIS, actual asynchronous I/O or ARM64 runtime coverage. The driver-side GET_RESET statistics effect cannot be rolled back by SDK validation.

Stale table-map controls cover an adapter arriving after enumeration, mixed known/new rows, wildcard zero, reorder, detached or unenumerable identities, immediate and pending refresh failures, malformed enumeration, table byte accounting, unchanged caller output on failure, and exactly one original GET or GET_RESET submission. Refresh errors remain visible even when cleanup deliberately changes LastError.

Set SDK_HANDLES_COMPILER_FLAGS=/D_USING_V110_SDK71_ before invoking the runner to exercise the real older Win32-mutex implementation with a modern compiler. That variant also runs a deterministic concurrent update: a test-only ReleaseMutex seam starts another thread after the map snapshot lock releases and waits at most five seconds for its real enumeration to remove an adapter. Both table rows must still translate using the original snapshot. This is Win32-mutex runtime and synchronization evidence, not certification with an old compiler. No production test hook is added.

For isolated evidence, pass an explicit fresh -OutputDirectory. The snapshot variant and ordinary modern x86/x64 runs should use separate directories. A separate real VS2012 compile using /Zc:forScope- provides partial older-toolchain evidence; VC6 compatibility still requires a real VC6 compiler. The packet read helper and new table loops explicitly reuse their loop variable to avoid repeated declarations under legacy for-scope rules.
