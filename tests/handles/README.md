# SDK handle and static table regressions

Run from the SDK root with tests\run_all.cmd, or run Run-Handles.ps1 -Arch x64 and -Arch x86 directly. The latter must execute on 64-bit Windows to cover genuine WOW64. VCVARSALL can select a toolchain; otherwise build_handles.cmd uses vswhere.

These three fixture source files are exact copies of the independently reviewed Task12a pre-implementation oracle. The retained console word 'baseline' identifies that oracle, not the source being tested. The runner compiles the real SDK translation unit with Win32 I/O and allocation seams. Constructor detection, wire types, mappings, table conversions and public calls remain real. Its x86 executable genuinely takes the WOW64 branch and obtains handles from full 64-bit enumerated identities.

Coverage includes valid and invalid mappings at every forward caller, stable surviving identities after enumeration reorder/removal, the final map slot, unrestricted generic OIDs, immutable SET/ADD/INSERT inputs, terminal-lived private I/O storage, independent immediate/terminal bytes, transactional GET/GET_RESET outputs, count and byte bounds, all returned handle translations, and arithmetic around the exported int byte boundary. A table of 16,385 rules proves that the SDK does not impose the driver's configurable policy cap.

The allocator seam applies only to the SDK translation unit. Large malformed capacities use guard pages; /EHa allows the baseline's faults to become failed assertions and unwind locks. Caught faults are failures, never successful cases. The runner records the source hash before compilation and after execution, preserves the actual child exit, and requires a complete final checks/RESULT footer consistent with that exit. Timeout, crash, source drift and missing/contradictory footers are invalid evidence (runner exit 2), separate from a complete passing or failing test result. The shim does not constitute kernel, NDIS, actual asynchronous I/O or ARM64 runtime coverage. The driver-side GET_RESET statistics effect cannot be rolled back by SDK validation.
